# Self-hosted autonomy four-hour review — 2026-07-26

## Verdict

The self-hosted system has a substantial, tested control plane, but it is not
yet fulfilling its central purpose: autonomously completing substantial real
MaskFactory work through one long-lived local model service with exception-only
Codex involvement.

Audit readiness estimates:

- control-plane/code completeness: 85–90%;
- working autonomous runtime: 45–55%;
- production qualification: 20–30%; and
- end-to-end completeness: 60–65%.

The binding claim remains:

`SELF_HOSTED_AUTONOMOUS_LLM_THROUGHPUT_INCOMPLETE`

Only three runtime evidence roots were produced in the same window: two route
fault drills and one interrupted-recovery drill, totaling 33 files and 266,072

Commits, tests, schemas, manifests, and receipts are supporting evidence only.
Acceptance must count real model requests, accepted project artifacts, terminal
reconciliation, and resource release.

## Critical integration gap

The committed supervisor primarily supervises fallback/advisory dispatch. The
committed campaign packet code validates and aggregates already completed
mission roots. Neither alone executes the required full chain:

`tracker selection → deterministic campaign construction → guarded local
self-hosted execution → patch/test/repair → terminal reconciliation → one
consolidated Codex packet`.

The direct next sequence is:

1. commit and focused-test the 25-mission engineering runtime controller;
2. add a guarded CLI launched through the shared-Pod lease wrapper;
3. wire the controller into the supervisor;
4. run a CPU fake-runtime 25-mission E2E proving restart, terminal accounting,
   and one-packet behavior;
5. run one real 25-mission Qwen campaign under one owned model-service
   lifetime;
6. qualify the visual critic/juror and run the governed 100-mask campaign; and
7. run three consecutive mixed campaigns meeting every Plan-27 SLO.

## Anti-spin correction

Until the first real 25-mission campaign is terminal:

- freeze non-defect Plan/schema/dashboard/receipt-format/hygiene work;
- count a wave only when it delivers executable integration plus focused tests
  or real terminal runtime evidence;
- classify static/unit-only progress as
  `STATIC_PASS_CONTROL_PLANE_ONLY`;
- cap bookkeeping and hygiene at 10% outside a documented blocking defect;
- prohibit successor packets without a material immutable-contract change;
- prohibit replacement clones/worktrees used to avoid checkout
  reconciliation; and
- record the production delta on every heartbeat.

### Authority reconciliation

The tracker gate for `MF-P6-19.01` must not require `MF-P6-18.04`: that later
acceptance row evaluates telemetry produced by the first real campaign. Once
the verified controller/CLI/supervisor/CPU-E2E foundation is present, selector
priority is the real 25-mission campaign ahead of pending telemetry or mask
rows. This changes neither the guarded runtime's prerequisite checks nor any
runtime-acceptance status.

This review does not mark any runtime acceptance item complete. It corrects
work selection so the remaining effort is spent on the product's actual
throughput gates.
